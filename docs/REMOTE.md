# 远程控制（Remote Control）

用手机浏览器操控电脑上正在运行的 AllAi：**聊天、Agent、创作**都能用。0.16.0 加入。
0.16.4 起手机网页有联网/推理/权限开关，列表长按可改名删除，进出对话有过渡动画。

```
手机网页  ──wss──▶  你的服务器（中继）  ◀──wss──  电脑上的 AllAi
   └────────── 端到端加密，中继只经手密文 ──────────┘
```

- 手机操控的是**电脑上的 AllAi 界面本身**：手机上打开一条聊天，电脑屏幕也切过去；
  手机上发的消息电脑上看得到，电脑上发的手机上也同步看到。
  **Agent 打开例外**：每台手机自己盯一条工作，不改电脑当前选中的那条。
- 电脑要开着、AllAi 要开着（窗口可以最小化，关掉窗口就是退出）。
  建议把 Windows 的「睡眠」关掉，不然睡着了手机就连不上。
- **「操控电脑」不开放给远程。**

## 安全

| 谁 | 能看到什么 |
| --- | --- |
| 中继服务器 | 只有密文、电脑和手机的随机编号、帧的大小和时间。不存任何东西，重启即清空，日志里只有「电脑上线/下线」。 |
| 没配对的人 | 什么都做不了：电脑只认配过对的手机的密钥，陌生设备打招呼直接被拒。 |
| 拿到中继口令的人 | 能冒充一台电脑登记到中继上，但解不开任何消息，也配不上你的手机。 |

怎么做到的（细节见 `electron/remote-protocol.ts`，电脑和手机用的是同一份代码）：

- **配对**：电脑生成一次性二维码，里面的密钥放在链接的 `#` 后面 —— 浏览器**不会**把 `#` 后面的内容发给服务器。
  手机用它和电脑换到一把这台手机专属的长期密钥。二维码 10 分钟过期、只能用一次。
- **每次连接**：双方各出一个随机数，派生出这次会话的 AES-256-GCM 密钥。
  每一帧都带顺序号参与加密，**被重放、调换顺序、篡改的帧都会解密失败**，电脑发现后立刻让这条会话作废重来。
- 手机上的密钥存在这个网页自己的本地存储里（IndexedDB 和 localStorage 各一份，别的网站读不到）。清掉网站数据、换浏览器就要重新配对。
- 电脑上的密钥和中继口令用 Windows 的凭据加密（DPAPI）存在 `~/.allai/remote.json`。
- 电脑本机的服务（127.0.0.1 上那个）没有鉴权，**手机永远碰不到它**：远程能做的事是写死的白名单，
  文件编号等参数都校验过。

**要知道的一个前提**：手机网页本身是从你的服务器下载的。如果服务器被人完全控制，
他可以把网页换成一个会偷密钥的版本 —— 这是所有「网页版端到端加密」共有的限制。
他**拿不到已经发生过的对话**（那些从没以明文经过服务器），但之后你再打开网页就可能中招。所以：

- 服务器系统和 1Panel 保持更新，SSH 用密钥登录；
- 电脑上「设置 → 远程」里能看到每台设备最近什么时候连过、做过哪类操作，看到不认识的就移除；
- 手机丢了：在电脑上把那台设备移除，它的密钥立刻作废。

远程权限（电脑上「设置 → 远程」）：

- **Agent 沿用电脑上的权限模式**（默认开）：关掉后，远程发起的任务里「全部放行」会降成「接受编辑」，Codex 的「全部放行」降成「自动」。
- **允许远程用管理员身份运行**（默认关）：打开后，电脑上开着管理员模式时，远程请求也以管理员身份跑本机 CLI。

## 部署（Ubuntu / Debian + 1Panel）

中继是一个 Node 程序（一个文件），手机网页也由它提供。只需要一个子域名，比如 `allai.example.com`。

### 1–2. 一键部署到服务器（在电脑上跑）

服务器上只需要 Docker（1Panel 自带）。在项目目录里：

```powershell
npm run remote:deploy
```

第一次会生成 `scripts\relay-deploy.env`，打开填好 `HOST`（如 `root@你的服务器IP`）和 `SSH_PORT`，再跑一次。
脚本会：

1. 配好免密登录（**只有第一次**要输一次服务器密码）；
2. 打包中继和手机网页，传到服务器的 `/opt/allai-relay`；
3. 用 Docker 启动中继，监听服务器本机的 **30778** 端口（端口在 `relay-deploy.env` 的 `RELAY_PORT` 改）；
4. 第一次部署时自动生成中继口令，最后在屏幕上打印出来 —— 电脑上 AllAi 要填这一串。

以后更新中继也是这一条命令，口令会一直沿用。其他命令：

```powershell
.\scripts\relay-push.ps1 status    # 运行状态 + 健康检查
.\scripts\relay-push.ps1 token     # 再看一次口令
.\scripts\relay-push.ps1 logs      # 看日志（Ctrl+C 退出）
.\scripts\relay-push.ps1 restart   # 重启
.\scripts\relay-push.ps1 down      # 停止
```

### 3. 1Panel 里配反向代理

1. 「网站」→「创建网站」→「反向代理」。主域名填 `allai.example.com`，代理地址填 `http://127.0.0.1:30778`。
2. 网站设置 →「HTTPS」：申请证书（Let's Encrypt），打开「强制 HTTPS」。**必须是 HTTPS**，手机上的加密功能只在 HTTPS 下可用。
3. 网站设置 →「反向代理」→ 编辑 →「源文」，确认有下面这几行（WebSocket 要用），没有就加上：

   ```nginx
   proxy_http_version 1.1;
   proxy_set_header Upgrade $http_upgrade;
   proxy_set_header Connection "upgrade";
   proxy_read_timeout 3600s;
   proxy_send_timeout 3600s;
   ```

4. 在任意电脑的浏览器打开 `https://allai.example.com/healthz`，显示 `ok` 就通了。

也可以放在已有域名的子路径下（比如 `https://example.com/allai/`，把 `/allai/` 代理到 `http://127.0.0.1:30778/`），
那样中继地址就填 `https://example.com/allai`。

### 4. 电脑上开启

AllAi →「设置」→「远程」：

1. 中继地址填 `https://allai.example.com`，口令填上面那串，保存；
2. 打开「开启远程控制」，状态变成「已连上中继」；
3. 点「生成配对二维码」。手机上打开中继网址，点「扫码配对」扫它（也可以直接用手机相机扫，会在浏览器里打开），再点「配对」。

可以在手机浏览器里「添加到主屏幕」，用起来像个 App。**iPhone 上主屏幕 App 和 Safari 的存储是分开的**：
先添加到主屏幕，再在主屏幕 App 里点「扫码配对」配对，这样杀掉后台也不用重配。

### 多台设备 / 多台电脑

- 每台手机、平板各扫一次码，各有各的密钥，可以单独移除。
- 同一个中继可以给多台电脑用（口令一样）。手机上可以配多台电脑，左上角切换。

## 排错

| 现象 | 原因 |
| --- | --- |
| 电脑上一直「正在连接中继」 | 地址不对，或反向代理没开 WebSocket（见第 3 步第 3 条）。 |
| 「中继口令不对」 | 电脑上填的和服务器 `.env` 里的 `RELAY_TOKEN` 不一致。 |
| 手机上「电脑不在线」 | 电脑关机/睡眠了、AllAi 退出了，或远程控制没开。 |
| 手机上「已经移除了这台设备」 | 电脑上移除了它，重新扫码配对即可。 |
| 扫码后「二维码已经失效」 | 过期了或已经用过，电脑上重新生成。 |
| iPhone 主屏幕 App 里又要配对 | 之前是在 Safari 里配的（和主屏幕 App 存储分开），在 App 里点「扫码配对」再配一次。 |
| 点「扫码配对」说没有相机权限 | iPhone「设置」里给 Safari 打开相机；或者点「从相册选图」，选一张二维码截图。 |

## 给维护者

- `relay/server.ts`：中继。只认两种身份（`desktop` 带口令、`device` 不带），只转发。
- `electron/remote-protocol.ts`：加密协议，电脑和手机共用，只准用 WebCrypto。
- `electron/remote.ts`：电脑端。配置、配对、会话、RPC；聊天/Agent 的操作转给界面执行，
  界面推回的状态在这里按消息 id 做差量后加密发给手机；创作和文件直接调本机接口。
- `components/useRemoteControl.ts`：界面这一侧。执行手机来的操作（用最新闭包，别用过期状态），
  有手机连着时才推状态（200ms 合并一次）。
- `mobile/`：手机网页（React），`npm run remote:build` 打进 `relay/dist/public/`。
